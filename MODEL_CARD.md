# Карточка модели

Итоговая модель — EfficientNet-B0, run `5fd5ed281bce46088edaef1277d0d4fd`. Обучение использовало аугментации `v2_augmented`. Test и сервис считают снимок версией `v1_baseline`, без обучающих аугментаций.

## Экспорт в ONNX

```powershell
$env:MODEL_ARTIFACT_PATH = "artifacts/best_model.pt"
poetry run python scripts/export_onnx.py
```

Файл `artifacts/best_model.onnx` в git не входит. Скрипт проверяет граф и пишет цифры в `experiments/onnx_report.json`.

- Вход `input`: float32, форма `batch × 3 × 224 × 224`.
- Выход `logits`: float32, форма `batch × 8`.

Сравнение на `tests/fixtures/black_rot.jpg`, тот же препроцессинг, что у сервиса. Сто запросов идут по одному снимку на CPU.

| | |
|---|---|
| Допуск atol | 1e-4 |
| Максимальное расхождение логитов | 9.54e-6 |
| Размер ONNX | 16061189 байт |
| Задержка PyTorch | 21.06 мс/запрос |
| Задержка ONNX | 5.61 мс/запрос |

Расхождение меньше допуска, предсказанный класс совпадает. На одном снимке ONNX примерно в 3.8 раза быстрее. Сервис пока вызывает PyTorch. На этапе Docker расчёт перейдёт на onnxruntime.

Модель обучена на лабораторных снимках восьми классов. Она не заменяет осмотр растения.
